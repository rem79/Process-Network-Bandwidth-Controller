시나리오 1: SAP / TMS 연동 송장 출력 오류 완벽 대응 (4단계)
STEP 1

내 PC (로컬 프로세스) 점검

• Real-time Live Sentinel 탭에서 TMS.exe 및 spoolsv.exe(프린터 스풀러) 확인
• CPU 100% 프리징 또는 실수로 대역폭 제한(Limit)이 걸려있는지 점검

STEP 2

중국/해외 서버 소켓 상태 점검

• TMS.exe 행의 [.. sockets] 버튼 클릭
• SYN_SENT: 서버 다운, VPN 끊김 또는 방화벽 차단
• LATENCY가 300ms 이상(빨간색)이면 국제망 회선 지연

STEP 3

서버 재부팅 대신 [✂️ Kill] 세션 리셋

• 중국 서버를 통째로 껐다 켤 필요 없이, 꼬여있는 소켓의 [✂️ Kill] 버튼을 누르면 1초 만에 세션이 초기화(TCP Reset)되어 송장이 즉시 출력됩니다.

STEP 4

Traceroute 국제망 병목 추적

• Diagnostic Toolbox 탭의 Visual Traceroute에 중국 서버 IP 입력
• 국내 구간 vs 한중 해저케이블 vs 중국 통신사 중 어디서 패킷 손실이 나는지 입증

시나리오 2: 웹사이트 / 사내 ERP가 느릴 때 (DNS vs 서버 판별)
💡
NSLOOKUP & DNS 벤치마크 활용:

Diagnostic Toolbox에서 도메인을 입력하여 KT, SK, LG, Cloudflare, Google 중 어느 DNS가 가장 빠른지 비교하세요. 응답이 빠른 DNS로 PC 네트워크 설정을 변경하면 첫 페이지 로딩 속도가 2~3배 빨라집니다.

💡
공유기(Wi-Fi) 문제 vs 상대 서버 문제 구분:

상단의 LOCAL NETWORK & ADAPTER DIAGNOSTIC에서 GATEWAY RTT가 5ms 이하라면 공유기와 내 PC는 최적 상태입니다. 이 상태에서 느리다면 100% 상대방 서버 또는 통신사 회선 문제입니다.
