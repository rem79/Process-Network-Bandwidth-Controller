PART 1. 각 탭별 기능 및 상세 사용법
TAB 1

⚡ Real-time Live Sentinel

• 실시간 트래픽 관제: 실행 중인 모든 프로그램의 다운로드/업로드 속도, CPU/RAM 점유율, 소켓 수를 실시간 표시.
• QoS 속도 제어: [Limit] 버튼을 눌러 슬라이더 또는 수치 입력(1 KB/s ~ 100 GB/s)으로 특정 앱의 대역폭을 캡(Cap)할 수 있습니다.

TAB 2

📊 Traffic Analytics & History

• 누적 사용량 추적: 오늘, 최근 7일, 30일 동안 어느 프로그램이 데이터를 가장 많이 썼는지 SQLite DB에서 분석.
• 컬럼 정렬: 컬럼 헤더(날짜, 앱이름, 전송량)를 클릭하여 오름차순/내림차순 정렬 가능.

TAB 3

🛡️ Active QoS Rules

• 윈도우 커널 정책 관리: 현재 윈도우 NetQosPolicy에 등록된 모든 속도 제한 규칙을 카드 형태로 확인.
• 원클릭 초기화: [Clear All Policies]로 모든 제한을 한 번에 해제 가능.

TAB 4

🌍 Global Cyber Map

• 글로벌 트래픽 레이더: 내 PC(한국)에서 미국(AWS, Google), 유럽, 아시아 등 전 세계 어느 서버로 데이터가 나가는지 네온 아크 라인으로 실시간 시각화.
• 우측 목록에서 목적지별 실시간 핑(ms) 확인 가능.

TAB 5

🛠️ Diagnostic Toolbox

• NSLOOKUP & DNS 벤치마크: 도메인을 입력하여 KT, SK, LG, Cloudflare, Google DNS 중 최속 DNS 비교.
• Visual Traceroute: 목적지 서버까지의 구간별(Hop) 라우터 경로와 핑 시각화.
• 원클릭 네트워크 응급 복구: PC 렉/DNS 꼬임 시 [Run Emergency Flush]로 1초 만에 DNS 캐시 청소 및 ARP 테이블을 초기화합니다.

MODAL

🔍 Supercharged Sockets Inspector

• 프로세스의 [.. sockets] 버튼을 누르면 열리는 상세 창.
• 도메인 & 국기 역추적: IP 숫자를 기업명(Netflix, AWS 등)과 국기(🇰🇷, 🇺🇸)로 자동 변환.
• [✂️ Kill] 버튼: 꼬이거나 멈춘 TCP 소켓만 1초 만에 강제 절단.

PART 2. 네트워크 & 시스템 핵심 용어사전 (알기 쉬운 한글 풀이)
PROTOCOL

TCP vs UDP

• TCP: 데이터 유실 없이 순서대로 주고받는 신뢰성 중심 방식 (SAP, 웹, ERP, 파일전송)
• UDP: 속도가 우선인 실시간 스트리밍, DNS 조회 방식

ADDRESS

Local vs Remote Endpoint

• Local: 내 PC 내부 IP와 프로그램이 열어둔 포트 번호
• Remote: 접속 중인 상대방 서버의 공인 IP와 포트 (예: :443 = 보안 웹, :3200 = SAP)

STATUS

소켓 상태 (ESTABLISHED / SYN_SENT / TIME_WAIT)

• ESTABLISHED: 정상 연결되어 실시간 통신 중
• SYN_SENT: 서버에 접속 요청을 보냈으나 답이 없음 (서버 다운, VPN 끊김, 방화벽 차단)
• TIME_WAIT: 통신 종료 후 정리 대기 중인 상태

SPEED

Latency (RTT 핑 지연시간)

• 내 PC에서 신호를 보내 서버가 응답하기까지 걸린 왕복 시간(ms).
• 🟢 <50ms (국내 초고속) / 🟡 50~150ms (아시아권) / 🔴 >150ms (미국/유럽 등 해저케이블 왕복)

REPAIR

DNS Flush & ARP Cache

• DNS Flush: 내 PC에 잘못 저장된 옛날 서버 IP 정보를 강제로 지우고 새로 받아오는 청소 작업.
• ARP Flush: 공유기와 내 PC 사이의 꼬인 하드웨어 주소 테이블을 초기화하는 작업.

ROUTING

Traceroute (Hop 경로 추적)

• 내 PC $\rightarrow$ 공유기 $\rightarrow$ 통신사 $\rightarrow$ 해외 서버까지 몇 개의 라우터(Hop)를 거치는지와 구간별 지연을 추적하는 기능.

PART 3. 실무 SAP / TMS 중국 연동 송장 출력 장애 대응 가이드 (SOP)
사내 송장 출력 아키텍처 이해하기 (3-Tier 연동 구조)

우리 회사는 출하 PC (SAP GUI 또는 웹 크롬) $\rightarrow$ SAP ERP $\rightarrow$ 중국 TMS 서버(운송/라벨 생성) $\rightarrow$ 한국 출하장 프린터(spoolsv.exe)를 거쳐 출력됩니다. 따라서 TMS.exe라는 전용 앱이 없더라도 아래 프로세스를 점검하시면 됩니다.

STEP 1

로컬 출하 PC 점검 (SAP GUI & 프린터)

• Real-time Live Sentinel 탭에서 saplogon.exe, chrome.exe, spoolsv.exe(프린터 스풀러) 검색
• CPU 100% 프리징 또는 대역폭 제한(Limit) 여부 확인

STEP 2

중국 TMS 서버 소켓 상태 확인

• saplogon.exe 또는 chrome.exe 행의 [.. sockets] 버튼 클릭
• 중국 서버 IP 연결 상태가 ESTABLISHED(정상)인지 SYN_SENT(서버 무응답/방화벽)인지 확인
• 핑(ms)이 300ms 이상이면 한중 회선 지연

STEP 3

서버 재부팅 대신 [✂️ Kill] 세션 리셋

• 중국 서버 전체를 재부팅할 필요 없이, 소켓 창에서 중국 서버와 꼬여있는 연결의 [✂️ Kill] 버튼을 누르면 1초 만에 세션이 초기화(TCP Reset)되어 송장 출력이 재개됩니다.

STEP 4

Traceroute로 국제망/해저케이블 증거 확보

• Diagnostic Toolbox 탭의 Visual Traceroute에 중국 서버 IP 입력
• 한국 통신사 vs 해저케이블 vs 중국 통신사 중 어디서 패킷 손실(Timeout)이 나는지 명확히 입증
